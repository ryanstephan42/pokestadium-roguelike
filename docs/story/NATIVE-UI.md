# Source-only native UI resources

The default-off `STORY_NATIVE_UI` adapter makes real native calls when invoked:
`rl_ui_init` acquires shared fonts, Pokemon icons and species/move text;
`sc_scene_draw` renders the prepared controller; input reads
`gPlayer1Controller->buttonPressed`. It does not read held buttons or invent a
repeat clock. The caller owns the display-list workspace, orthographic setup,
input polling, frame submission and task fences.

`sc_native_ui_acquire` creates only a nested **graphics resource** pool scope,
checks its creation and the shared resource initializer result, and retains it
until explicit release. This is not Expansion Pak admission and does not
allocate `ScUi` or `ScUiBattleRequest`. The owner must supply the admitted
43,472-byte controller and 1,560-byte request, plus driver and native adapter
backing. Actual IDO `sizeof` constants additionally measure `ScNativeUi` at
24 bytes and retained `ScNativePak` at 1,484 bytes; the runner emits target
driver/controller/request size constants too. These are layout facts, not
full arena, stack or display-resource fit clearance.
The resource scope must be the top scope for acquisition, icon prefetch and final
result/release calls; per-battle scopes must drain/pop before result delivery. No root,
BATL generation or native image pointer is placed in UI request values.

Only one graphics binding is active. Preparation is once per acquisition, and
the driver must reference that exact prepared UI and Pak device. The first
input call retains the exact driver object; copied/exited driver values cannot
retire another campaign. A monotonically increasing Pak binding ID is captured
at acquisition, preventing release/rebind of the same backend object from
silently satisfying a stale graphics binding. This is backend lifetime identity,
not a BATL generation or arena permit. Release
refuses nested scopes, a still-open prepared campaign, pending submissions/journals/battles or an unfenced
display lifetime. `tasks_retired` is the owner's declaration that its native
fence completed, not a permit generated by this adapter.

## Isolated Pak backend

`sc_native_pak.[ch]` extracts the existing `sc_pak_probe.c` raw filesystem
backend. The probe retains its synchronous static-backing lifecycle and now
calls the extracted implementation. This package does not add a build hook;
the owner must link the backend alongside the probe or native adapter.

Zeroed `ScNativePak` backing belongs to the caller. Binding fixes the controller;
begin/end acquire/release `Cont_BlockEepromQueue` around the entire storage
transaction. Only one serialized, non-reentrant session may be active. Device
callbacks refuse use outside that session. The native UI wraps prepare/input/
finish storage calls in sessions; its launch callback remains non-reentrant
as required by the typed driver. Observe calls do not perform Pak I/O.

Reads validate raw identity replicas, inode mirrors/checksums and every directory
chain with `rl_pak_validate_note`. No `osPfsInitPak` repair or block-zero write is
introduced. The exact story note/company/game/size is checked before opening;
allocation uses the existing `rlPfsAllocateFile` path, validates the resulting
note/physical device again, zeros only its pages and sets the original
directory status. Errors propagate as `ScSaveStatus`, never successful defaults.

A valid physical-device identity is retained across sessions. A replacement Pak
is refused rather than quietly becoming the target of a pending retry. Once
the note has been observed, deletion is refused rather than silently recreated.
Only explicit release/rebind resets these identities; the owner must not do that
while a campaign transaction is pending.

## Proof boundaries

`bash host_tests/run_story_native_resources.sh` compiles the actual adapters,
exercises real metadata validation and journal APIs with synthetic raw OS
outcomes, then compiles actual backend/UI/probe target TUs using IDO and N64
headers. It covers session/binding refusal, metadata read failures, every I/O
failure during finite creation, allocation/errors, range/alignment, sticky
physical identity, note deletion, successful journal round-trip, edge input,
nested resource lifetime and explicit task-retirement refusal.
The actual checked resource helper also refuses all 13 allocation failures,
missing/short font/icon/text archives and all five required glyph/name files,
and restores a borrowed font descriptor on scope retirement.

## Learning under a live battle child scope

Parent-scope input/drawing prefetch current party/offer icons before launch.
The story icon renderer consumes only validated cached pixels; it never lazily
allocates during drawing. A missing cache explicitly refuses presentation,
including under a child scope. Ordinary non-story RL lazy loading is unchanged.

The native adapter checks the actual pool-state ancestor chain for its captured
graphics parent. Descendant input/drawing also require the retained driver/UI/Pak
identity and an accepted live battle in `SC_LEARNING` or `SC_BATTLE`. These
calls perform no icon acquisition or Pak session/I/O; controller learning is
the existing in-memory transaction. Final finish and release still require the
parent to be top, after owner worker drain/pop. No new service permit is created.

The child-learning fixture launches a value request, feeds a synthetic KO into
real observe/progression, chooses decline through real input while a pool child
is live, and returns to battle. Allocation and raw Pak I/O counters stay
unchanged. Missing cached pixels and an unrelated ancestor chain refuse; finish
and release refuse until child retirement. This is host fixture evidence, not
native task execution, DMA or battle-scope authority.

Font/pool/display/OS calls are host fixtures, not native execution. Resource
budgets and full stack/allocator fit are not established by these tests.
Host compilation of the unchanged text-formatting body suppresses its existing
32-bit pointer/sign/format/decomp warnings only in that translation unit; the
checked acquisition/getter and other adapter TUs retain `-Werror`. Text-format
rendering is not exercised by those native-resource fixtures.
The `STORY_NATIVE_UI` branch uses checked font control/archive/glyph and text
archive/substitution-table acquisition instead of the legacy unchecked helpers.
Pool cleanup callbacks restore borrowed font, text and renderer globals only
after their temporary allocations retire. Default RL/vanilla paths are unchanged.
Arena/backing/async launch/pause/observe/drain scheduling still
belong to the parent. No dispatcher/build/KO changes, emulator run, full gate
or visible-campaign acceptance are included.

## Coordinated presentation loop and checked display

`sc_native_loop.[ch]` consumes the owner ABI imported from exact `08766a8` and
`5869a454`. The caller supplies zeroed external loop/display control; `open`
acquires the exact arena-issued backing tuple, validates it, then acquires
display, Pak binding, retained UI resources and the existing operation-ID driver.
`step` and `close` return `ScStatus`. A failed open retains the lease until a
validated close can retire only acquisitions made by that loop.

The driver queues copied battle values during input, but actual owner submission
occurs only after the Pak session and display frame have ended. PENDING/refusal
owns no service work and restores the driver's A-retry state. A failed frame
also cancels an unsubmitted queue without losing the checkpoint. Accepted
running battles are pumped only by owner polling; the loop does not overwrite
their display with menu frames or process campaign input.

Events use the exact caller-admitted `backing.event`. PENDING/refusal/NONE
payloads are ignored. Nonzero operation IDs must match driver, request and UI;
event kinds, observation bounds, outcomes and strictly increasing per-operation
serials are checked before dispatch. Exhaustion refuses without wrapping or
retiring the lease. Held LEARNING observations go through real driver/core
observe and must establish `SC_LEARNING`. The first held frame presents without
input; subsequent frames settle actual learning. Resume uses the same held
serial and copies settled state/combat only in `SC_BATTLE` with no learn mask.
PENDING retries the exact values without polling or accepting further input.

DRAINED must come from the owner's worker/service/permit retirement and BATL pop.
It dispatches finish; unavailable Pak acquisition retains the drained operation
without polling a successor. Once finish starts a journal transaction, save
retry belongs solely to the UI and never replays that event/reward. Close
requires campaign exit and no queued/held/drained work, completes real task
fences, retires graphics before owner backing, and retains the lease on owner
release PENDING. Owner validate refusal never authorizes cleanup.

`sc_native_display.[ch]` checks actual workspace/context/framebuffer allocations.
The story-only workspace helper captures and restores borrowed workspace/head;
per-frame activation preserves the retained next-frame command prefix and
restores the paused native workspace. Guarded raw stage/image helpers restore
the captured stage pointer, framebuffer pointer and clipping rectangle without
emitting commands or copying fade/frame state into a borrowed context. Each
submitted UI frame is fenced before resume; stage-close submissions are fenced
again before scope retirement. Ordinary stage/workspace/framebuffer functions,
signatures and default code paths remain unchanged.

IDO layout facts: loop 128 bytes, display 136 bytes, event 80 bytes. Own frames
are loop open/step/close 72/64/32 bytes, private poll 64, private finish 32;
display acquire/begin/end/release 56/32/32/32; checked workspace acquisition 40.
These exclude callees, owner callbacks, interrupt/OS/task stacks and full peak.
Display requests two 65,536-byte workspaces, a 76-byte restoration record,
a 36-byte stage context and two 614,480-byte framebuffer records
(640 * 480 * 2 pixels + 16-byte header + 64 alignment allowance).
Requested total is 1,360,144 bytes; the tracked pool's 16-byte rounding/headers
and 32-byte scope record bring display scope consumption to 1,360,288 bytes.
Fonts/icons/text, UI arena backing, BATL and owner storage are additional.
This is not combined candidate fit approval.

`bash host_tests/run_story_native_display.sh` exercises actual acquisition and
tracked workspace/context/framebuffer/restore function slices against synthetic
pool/OS/command outcomes: seven finite scope/allocation failures, borrowed
globals, preserved child context, open-frame/top-scope refusal and retirement
fences. The resource runner also compiles full display and guarded native helper
TUs with IDO. Its owner-bound loop fixtures cover post-Pak submission retry,
ignored pending payload, serial exhaustion/staleness, held KO presentation,
learning and resume retry, drained finish/save retry, validate refusal and
release PENDING. Normal and ASan/UBSan results are HOST evidence, not native
visible execution or allocator/service authority.
Successful close permits reuse of the same small loop/display control object.
Open resets exit/queue/hold/event-serial bookkeeping for the new lease only
after refusing an already acquired lifetime; pending retirement cannot rebind.
