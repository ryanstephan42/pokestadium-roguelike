# Source-only native UI resources

The default-off `STORY_NATIVE_UI` adapter makes real native calls when invoked:
`rl_ui_init` acquires shared fonts, Pokemon icons and species/move text;
`sc_scene_draw` renders the prepared controller; input reads
`gPlayer1Controller->buttonPressed`. It does not read held buttons or invent a
repeat clock. The caller owns the display-list workspace, orthographic setup,
input polling, frame submission and task fences.

`sc_native_ui_acquire` creates only a nested **graphics resource** pool scope,
checks its creation and the shared resource initializer result, and retains it
until explicit release. This is not Expansion Pak admission and does not
allocate `ScUi` or `ScUiBattleRequest`. The owner must supply the admitted
43,472-byte controller and 1,560-byte request, plus driver and native adapter
backing. Actual IDO `sizeof` constants additionally measure `ScNativeUi` at
24 bytes and retained `ScNativePak` at 1,484 bytes; the runner emits target
driver/controller/request size constants too. These are layout facts, not
full arena, stack or display-resource fit clearance.
The resource scope must be the top scope for acquisition, icon prefetch and final
result/release calls; per-battle scopes must drain/pop before result delivery. No root,
BATL generation or native image pointer is placed in UI request values.

Only one graphics binding is active. Preparation is once per acquisition, and
the driver must reference that exact prepared UI and Pak device. The first
input call retains the exact driver object; copied/exited driver values cannot
retire another campaign. A monotonically increasing Pak binding ID is captured
at acquisition, preventing release/rebind of the same backend object from
silently satisfying a stale graphics binding. This is backend lifetime identity,
not a BATL generation or arena permit. Release
refuses nested scopes, a still-open prepared campaign, pending submissions/journals/battles or an unfenced
display lifetime. `tasks_retired` is the owner's declaration that its native
fence completed, not a permit generated by this adapter.

## Isolated Pak backend

`sc_native_pak.[ch]` extracts the existing `sc_pak_probe.c` raw filesystem
backend. The probe retains its synchronous static-backing lifecycle and now
calls the extracted implementation. This package does not add a build hook;
the owner must link the backend alongside the probe or native adapter.

The shared story note name/extension live with the resident CRC helper in
`sc_crc.c`, not the cold codec in `sc_save.c`. The resident backend needs these
unchanged identity bytes even when the codec is unloaded. The linked residency
checker must reject resident references into cold storage.

Zeroed `ScNativePak` backing belongs to the caller. Binding fixes the controller;
begin/end acquire/release `Cont_BlockEepromQueue` around the entire storage
transaction. Only one serialized, non-reentrant session may be active. Device
callbacks refuse use outside that session. The native UI wraps prepare/input/
finish storage calls in sessions; its launch callback remains non-reentrant
as required by the typed driver. Observe calls do not perform Pak I/O.

Reads validate raw identity replicas, inode mirrors/checksums and every directory
chain with `rl_pak_validate_note`. No `osPfsInitPak` repair or block-zero write is
introduced. The exact story note/company/game/size is checked before opening;
allocation uses the existing `rlPfsAllocateFile` path, validates the resulting
note/physical device again, zeros only its pages and sets the original
directory status. Errors propagate as `ScSaveStatus`, never successful defaults.

A valid physical-device identity is retained across sessions. A replacement Pak
is refused rather than quietly becoming the target of a pending retry. Once
the note has been observed, deletion is refused rather than silently recreated.
Only explicit release/rebind resets these identities; the owner must not do that
while a campaign transaction is pending.

## Learning under a live battle child scope

Parent-scope input/drawing prefetch current party/offer icons before launch.
The story icon renderer consumes only validated cached pixels; it never lazily
allocates during drawing. A missing cache explicitly refuses presentation,
including under a child scope. Ordinary non-story RL lazy loading is unchanged.

The native adapter checks the actual pool-state ancestor chain for its captured
graphics parent. Descendant input/drawing also require the retained driver/UI/Pak
identity and an accepted live battle in `SC_LEARNING` or `SC_BATTLE`. These
calls perform no icon acquisition or Pak session/I/O; controller learning is
the existing in-memory transaction. Final finish and release still require the
parent to be top, after owner worker drain/pop. No new service permit is created.

The child-learning fixture launches a value request, feeds a synthetic KO into
real observe/progression, chooses decline through real input while a pool child
is live, and returns to battle. Allocation and raw Pak I/O counters stay
unchanged. Missing cached pixels and an unrelated ancestor chain refuse; finish
and release refuse until child retirement. This is host fixture evidence, not
native task execution, DMA or battle-scope authority.

Font/pool/display/OS calls are host fixtures, not native execution. Resource
budgets and full stack/allocator fit are not established by these tests.
Host compilation of the unchanged text-formatting body suppresses its existing
32-bit pointer/sign/format/decomp warnings only in that translation unit; the
checked acquisition/getter and other adapter TUs retain `-Werror`. Text-format
rendering is not exercised by those native-resource fixtures.

## Combined lower-pool admission blocker

The pre-successor Moon/UI link after the identity-storage correction has
`heap_BSS_START = 0x80127450`. Even allowing the entire lower 4 MiB up to
`0x80400000`, only 2,984,880 bytes remain; actual reservations can only reduce
that ceiling. The simultaneously retained accepted display (1,360,288 bytes),
cold story RAM image (204,192 bytes), and linked native fragment 62 RAM image
(815,216 bytes) leave at most 605,184 bytes.

The original BATL entry additionally allocates two 131,072-byte display-list
workspaces (`func_80005E40(0x20000, 0)`) and three 320-by-240 16-bit color images
plus one same-sized depth image (`func_80007444(0, 1, 3, 1, 2, 1)`).
Those payloads alone need 876,544 bytes, exceeding that remainder by
**271,360 bytes**, before their headers/scopes, fonts/icons/text, models,
archives, or loader staging. This is a conservative source/link lower-bound
refusal, not a measured native peak or completed stack budget.

The accepted all-lower-pool display therefore cannot be joined unchanged to
this native layout. Any relocation of its retained buffers into admitted
Expansion Pak storage must preserve exact ownership, task fencing and borrowed
state restoration; an 8 MiB machine alone does not enlarge the lower pool.

The shared arena's `sc_ma_data` lease supports exclusive mutable,
non-executable backing without publishing it as a callable module or leaving
it in loader staging. It refuses execute mapping, module sealing, concurrent
leases, release while held, stale tickets and exhaustion. This primitive does
not certify GPU/VI retirement: the owner must retain it until the actual
pre-pop retirement and final release protocol succeeds. Its host fixture maps
the exact two-framebuffer payload with a 64-byte-aligned subrange even when the
allocation starts only 32-byte-aligned, and separately checks retained
fail-stop ownership. This is not native allocator/display admission.

`sc_native_memory.[ch]` builds the private campaign tuple from one held data
lease in that same arena: UI/request/Pak/driver/event, owned submitted/resume
values, and two exact pixel spans. Alignment slack is charged once and does
not overlap the callable image allocation. It zeros only controls, not pixel
storage. The native path writes back then invalidates the newly exclusive,
64-byte-aligned pixel range before publishing it, preventing old dirty CPU
lines from later overwriting RDP output; this is not scheduler/VI admission.
Exact tuple validation refuses changed pointers, sizes, seed, ticket and stale
lifetimes, and binds the release allocation handle to the held lease before
and after the retirement callback. Acquisition OOM or ticket exhaustion
publishes a completely zero output tuple. Actual IDO rounds the value/control
storage to 49,664 bytes; the data allocation charges 1,278,528 bytes including
both pixel spans and 64 bytes of alignment slack. The external memory control
is 64 bytes. These are target layout charges, not whole-campaign peak proof.

Loop/display and retirement controls stay outside the freed allocation:
`sc_native_loop_close` still accesses its control after the owner release
callback returns. Memory release refuses outstanding UI/display/Pak work and
requires the owner's real retirement callback while scheduler exclusion is
held. Pending/refusal retains the whole lease. The focused host test uses a
simulated retirement callback and therefore does not prove native VI safety.
The `STORY_NATIVE_UI` branch uses checked font control/archive/glyph and text
archive/substitution-table acquisition instead of the legacy unchecked helpers.
Pool cleanup callbacks restore borrowed font, text and renderer globals only
after their temporary allocations retire. Default RL/vanilla paths are unchanged.
Arena/backing/async launch/pause/observe/drain scheduling still
belong to the parent. No dispatcher/build/KO changes, emulator run, full gate
or visible-campaign acceptance are included.

## Owner observation and learning transaction

`sc_native_operation.[ch]` is the cold-code operation producer, using the
retained external lifetime control and its admitted DATA value storage.
Submission compares the entire request to a freshly derived canonical UI
request before accepting copied values. Every subsequent submit, observe,
poll and resume revalidates the complete live request against that accepted
copy after lifetime validation and before processing events or settlements.
Any changed byte fails the transaction and retains backing; restoring the
request cannot recover that failed operation. Observations project the same pure
combat transition the UI consumes, retain a private full-event copy, and
establish the learning hold before delivery or presentation. Serial exhaustion,
altered queued events, invalid progression, and altered settlements retain an
explicit failed transaction. Pending observations cannot be overwritten.

The shared `backing->event` is an output-only buffer that is all zero between
deliveries. The owner keeps the queued event identity only in its retained
`pending` copy and leaves the shared buffer clean when queuing. Poll refuses and
fail-stops if any output byte is non-zero on entry: a foreign, injected or
replayed write is erased and never delivered. It also refuses if the retained
identity no longer matches the current operation, serial, kind or held serial.
Only then does it write the retained event once. `sc_native_loop` no longer
pre-clears `kind`; it consumes the delivered event and zeroes the whole buffer
after every poll (delivered, NONE, PENDING or refused), so no event survives
into the next poll.

Resume requires exact operation/held serial and the admitted loop's completed
presentation marker. It replays each pending member's actual accept/reject and
selected move-slot transition, then compares the complete settled state; it
cannot accept an unrelated state mutation or replay an already consumed hold.
Repeated raw zero-HP observations carry current party values but award XP only
on the first KO. The direct KO award API still rejects duplicate awards.

The focused runner `bash host_tests/run_story_native_operation.sh OUT` checks
actual producer/pure UI and combat code with injected lifetime validation.
It flips every accepted request byte at all four callback boundaries and checks
refusal without modifying stored progression, queued events or held settlements.
It also writes every event byte into the clean output at running, held and
delivered (replay) points, and alters the retained identity, all of which must
be refused. `bash host_tests/run_story_native_resources.sh` drives the actual
`ScNativeLoop` into this kernel through the owner callbacks:
- queued OBSERVE and held LEARNING are delivered once;
- the learn screen is presented and the move choice settled;
- resume runs through the owner;
- the buffer is zero after each step;
- each of the event bytes injected before delivery is refused;
- a replayed delivered event is refused.

DRAINED has no owner producer yet, so it is not tested through the loop.
Its lifetime view is explicitly not a target ABI fixture; actual IDO compilation
uses the production lifetime header. This unit does not launch native combat,
publish DRAINED, or authorize release. Actual callback/dispatcher wiring,
service/BATL retirement, complete stack/fit, and native validation remain required.

## Retained crash-screen reference

Native scheduler `func_800015A8` publishes a non-NULL image to
`gCrashScreen.frameBuf`. Its NULL/repeated-line fallback does not replace that
reference; the fault thread can later draw into and swap the retained buffer.
Consequently scheduler/VI fallback alone cannot authorize upper-pixel reuse.

`sc_native_crash_restore` restores the actual startup-reserved 320x240 RGBA16
crash buffer at uncached `0xa07da800` on an 8 MiB machine. This is the existing
`crash_screen_init` tail `[0x7da800,0x800000)`, outside the arena ending at
`0x7da7e0`; it is not an allocation or the 640x1 scheduler fallback. The existing
crash draw-info height field remains 16. An exact authenticated scheduler token,
quiescent worker, empty request/DONE queues and retired task/frame references
are required under one interrupt exclusion. A bounded owner callback must
authenticate pins, fallback and native mode without blocking or allocating.
The helper restores/readbacks crash draw info, does not submit or change VI,
and does not authorize freeing. Actual retirement must be checked again.
IRQ exclusion alone cannot retire local pixels captured by the fault thread.
The guarded `sc_crash_active` latch is set in actual fault-thread entry before
stopping the faulted thread, waiting or drawing, and is never cleared. Once
latched, restoration permanently refuses and the owner must retain backing.
The fixture extracts actual thread-entry and rectangle-render bodies, models
a non-game-thread fault, checks refusal while waiting and after local capture,
and confirms retained pixels remain available for the real draw loop.

`bash host_tests/run_story_native_crash.sh OUTPUT` covers refusal, task/frame
states, nested interrupt restoration and corrupt/readback failure, then joins
the helper to the actual extracted DP token/scheduler code. It reproduces the
retained crash alias after real NULL transitions and restores it without an
extra submission before the retirement check succeeds. OS/VI remain simulated;
the runner also compiles the actual crash helper with target IDO. These are
source/HOST/target-compilation checks, not native crash/scanout acceptance.

`sc_native_lifetime` pairs the admitted memory tuple with exact external
loop/display/retirement controls and the actual native scheduler fallback.
It revalidates immutable fallback descriptor identity, lease/handle/pins and
8 MiB/lower-pool policy on every live callback. Crash restoration precedes
the successful retirement check; scope cleanup must precede finalization.
Final latch/check/data-end/free execute under bounded interrupt exclusion;
the pure allocator has no OS waits or submission. A fault already active
refuses release permanently. After physical free, only external controls and
immutable pointer values may be read; a pending DP-token release retries
without memory validation, cleanup replay or another free.

`bash host_tests/run_story_native_lifetime.sh OUTPUT` joins the actual owner,
data allocator, retirement helper, DP slices, crash restoration and loop-close
retry. It protects retired control pages against reads and forces post-free
token-release pending twice before success. It also checks crash-active refusal
and interrupt exclusion at physical release. Lower cleanup is already retired
in this focused fixture; battle submission, learning events, dispatcher and
full memory/stack fit are not exercised or accepted by this lifetime proof.

## Coordinated presentation loop and checked display

`sc_native_loop.[ch]` consumes the owner ABI imported from exact `08766a8` and
`5869a454`, with framebuffer/retirement extensions `723b302` and `88fe18f`.
The caller supplies zeroed external loop/display control; `open`
acquires the exact arena-issued backing tuple, validates it, then acquires
display, Pak binding, retained UI resources and the existing operation-ID driver.
`step` and `close` return `ScStatus`. A failed open retains the lease until a
validated close can retire only acquisitions made by that loop.

The driver queues copied battle values during input, but actual owner submission
occurs only after the Pak session and display frame have ended. PENDING/refusal
owns no service work and restores the driver's A-retry state. A failed frame
also cancels an unsubmitted queue without losing the checkpoint. Accepted
running battles are pumped only by owner polling; the loop does not overwrite
their display with menu frames or process campaign input.

Events use the exact caller-admitted `backing.event`. PENDING/refusal/NONE
payloads are ignored. Nonzero operation IDs must match driver, request and UI;
event kinds, observation bounds, outcomes and strictly increasing per-operation
serials are checked before dispatch. Exhaustion refuses without wrapping or
retiring the lease. Held LEARNING observations go through real driver/core
observe and must establish `SC_LEARNING`. The first held frame presents without
input; subsequent frames settle actual learning. Resume uses the same held
serial and copies settled state/combat only in `SC_BATTLE` with no learn mask.
PENDING retries the exact values without polling or accepting further input.

DRAINED must come from the owner's worker/service/permit retirement and BATL pop.
It dispatches finish; unavailable Pak acquisition retains the drained operation
without polling a successor. Once finish starts a journal transaction, save
retry belongs solely to the UI and never replays that event/reward. Close
requires campaign exit and no queued/held/drained work and refuses retirement
during a Pak session. It closes display admission once, fences work, restores
borrowed stage/image/rectangle/workspace state, and calls the mandatory owner's
`retire_display` before popping any graphics/resource/display scope. PENDING or
refusal retains all scopes, descriptors, pixels and controls; retries do not
resubmit closure or reopen input. Every cleanup retry revalidates retirement,
even after an earlier SC_OK. Final cleanup emits no new display task or swap.
Owner release follows cleanup and must revalidate retirement; PENDING retains
the lease and external controls. Owner validate refusal never authorizes cleanup.

`sc_native_display.[ch]` checks actual workspace/context allocations and two
owner-admitted upper-arena framebuffer spans. Each span must be exactly 614,400
bytes, 64-byte aligned, mapped cached KSEG0 wholly within
`[0x80400000, 0x807da7e0)`, without overflow or overlap. Shape checks do not
establish allocator ownership: owner acquire/validate owns admission and exact
lease identity. The display embeds two image descriptors in external control
backing and initializes them with unchanged `func_800062E4`, without allocating
or touching pixels. No second arena, lower-pool fallback or pool enlargement
is introduced.
The story-only workspace helper captures and restores borrowed workspace/head;
per-frame activation preserves the retained next-frame command prefix and
restores the paused native workspace. Guarded raw stage/image helpers restore
the captured stage pointer, framebuffer pointer and clipping rectangle without
emitting commands or copying fade/frame state into a borrowed context. Each
submitted UI frame is fenced before resume; stage-close submissions are fenced
again before owner retirement. **A task fence does not retire VI scanout.**
The owner callback must actually submit/drive an admitted previous or safe
fallback framebuffer, drain A8C/A9C/AAC and queued task/descriptor references,
and check actual VI current/next outside both spans. A NULL previous context
is not safety evidence. Owner authority must prevent new lease-referencing
submissions racing between the check and cleanup. The UI cannot fabricate
that scheduler/allocator authority. Ordinary stage/workspace/framebuffer functions,
signatures and default code paths remain unchanged.

IDO layout facts: loop 148 bytes, display 176 bytes, event 80 bytes. Own frames
are loop open/step/close 80/64/48 bytes, private poll 64, private finish 32;
display acquire/begin/end/retire/release 64/32/32/32/24;
private span validation 40; checked workspace acquisition 40.
These exclude callees, owner callbacks, interrupt/OS/task stacks and full peak.
Display requests two 65,536-byte workspaces, a 76-byte restoration record,
and a 36-byte stage context: 131,184 requested bytes. Actual tracked pool
rounding/headers/scope consume 32 + 96 + 131,104 + 64 = **131,296 bytes**.
The predecessor's two lower framebuffer records cost 1,228,992 bytes including

External loop/display/descriptor backing belongs to the owner and must be

This is not combined candidate fit approval.

### Stage frame handoff

The checked display submits and fences its own frame. When that happens inside a
`func_800078D4` stage callback, the wrapper's trailing `func_80007778` would
submit a second, empty native frame. Under `STORY_NATIVE_UI` only, the resident
wrapper therefore arms a one-callback marker. Before each callback it records
`gDisplayListHead` and clears the marker. After a fully successful
`sc_native_display_end` (submit, fence, context restore, workspace suspend and
image restore), the display calls `func_800078D4ConsumeStory()`. The wrapper
skips its outer submission only when the marker was set during this callback
and the native command head is unchanged. It clears the marker immediately
after every callback and restores the caller's marker state when it returns, so
nested wrappers stay correct. A refused display end, a marker call outside an
armed callback, or a callback that also emitted native commands keeps the
ordinary outer submission. The marker never carries over to the next callback
or frame. `func_80007820` is unchanged, and the vanilla build has no marker.
Gameplay held frames must not emit native graphics before the story frame.

`host_tests/run_story_native_display.sh` extracts the actual guarded block and
the `func_800078D4` body. Under normal HOST and strict ASan/UBSan builds, it
checks the following submission sequences:

- a held frame produces exactly one story submit and fence, with no trailing
  native submit;
- ordinary frames keep their native submit;
- a refused display end keeps the native submit;
- a nested wrapper resolves the inner and outer callbacks independently;
- a dirty command head keeps the native submit;
- the frame after a held one does not inherit the marker;
- a held last frame is resolved per callback;
- a standalone display frame is never marked.

### Production retirement helper and scheduler exclusion

`sc_native_retirement.[ch]` supplies the production, nonblocking retirement
mechanism; allocator admission, lease pins, crash-buffer restoration and final
free remain owner-owned. The owner retains zeroed `ScNativeRetirement`, loop
and display controls **outside the allocation being freed**. Acquire binds exact
admitted spans, embedded descriptors and the live native `D_80083CA0.unk_9E0`
fallback, plus an owner validation callback. Validation precedes descriptor
reads and repeats after each atomic scheduler snapshot. It must establish exact
physical lease/descriptor identities, pins, native presentation mode and all
external-reference lifetimes; pointer shape is not admission.

The `STORY_NATIVE_UI`-only DP seam admits one nonwrapping generation token bound
to the exact token object, external control and actual Game Thread ID 6. Acquire
requires DP waiting at its receive boundary (`unk_A8A`), empty request queue and
consumed prior DONE. DP Thread 5 has priority 40; Game Thread 6 has priority 20,
so the game observes this boundary after DP blocks on receive. Snapshots disable
interrupts briefly to copy A8C/A9C/AAC, queues, RSP/RDP task states, native
fallback, VI current/next and crash framebuffer. No blocking queue operation
occurs with interrupts disabled. While held, ordinary `func_80001BA8` enqueue
and `func_80001B7C` DONE consumption explicitly log through `osSyncPrintf` and
stop the misusing thread; they do not silently drop work or allocate debug text.

Step consumes at most one DONE and enqueues at most one genuine NULL request
per call through
the actual worker's `0152C/015A8` native 640x1 RGBA16 repeated-line protocol.
No direct VI swap, NULL stage-helper invocation or fabricated descriptor is
used. Pending requests retain the token/control and all owner pins. Inspection
drains every frame descriptor/work reference without dereferencing foreign
descriptors, waits for RSP/RDP/task completion, and requires both non-NULL VI
pointers physically normalize to the admitted native fallback. At least one
NULL request must complete, even if pointers already look safe. The helper
checks fresh state on every call, never treating an earlier OK as permanent.
`sc_native_retirement_check` only refreshes inspection; it does not enqueue,
consume DONE or free. `sc_dp_quiescent` authenticates the exact token and permits
an owner's brief outer IRQ fence around a quiescent-only restoration.

The actual NULL worker branch leaves `gCrashScreen.frameBuf` unchanged.
Once the other references drain, a NULL or lease-aliased crash pointer refuses
retirement. Owner authority must restore an admitted full-size crash buffer,
not the one-line VI fallback, and recheck. No crash-buffer authority or storage
is invented here.

After lower cleanup, `sc_native_retirement_finalize(control, retire_backing)`
rechecks retirement and invokes the exact owner free callback **while scheduler
exclusion is still held**. Pending/refusal retains backing. Callback OK records
the one-way `backing_retired` phase, then releases only the external token:
no images, spans, fallback, external display or owner validation is touched.
A post-free token-release failure retains exclusion; retry never replays the
callback. `sc_native_retirement_release` is an abort without backing free,
not the final-free API.

The focused `run_story_native_retirement.sh` runner uses the actual helper,
extracted tracked DP seam/header/producer guards and `0152C/015A8` bodies.
Synthetic OS/VI outcomes cover delayed DONE/current/next, aliases, references
returning after OK, crash retention/restoration, invalid native mode, token
thread/object/generation/exhaustion, guarded producer misuse, read-only checks,
free refusal and actual descriptor free followed by token-release retries.
Normal and strict ASan/UBSan modes plus full DP/helper IDO objects are source/HOST
evidence, not installed native VI, owner callback pairing or combined-fit proof.
IDO measures token 8, snapshot 92 and external retirement control 156 bytes.
Helper own frames: acquire/check/step/abort-release/finalize 24/32/40/24/32;
